# CheckYourMorpho: Покроковий План Реалізації та Журнал Прогресу

Цей документ є головною інженерною дорожньою картою (Implementation Roadmap) та журналом відстеження прогресу розробки системи **CheckYourMorpho**.
Він призначений для використання поточним та всіма наступними AI-агентами та інженерами.
При виконанні кожного завдання статус відповідного пункту повинен оновлюватися на виконаний (`[x]`), а в секції «Журнал виконання робіт» фіксуватися короткий звіт про створені або змінені компоненти.

---

## 1. Загальні Архітектурні Принципи

1. **Мова та Стек**:
   - Чистий JavaScript (ES2022+, ESM модулі `import/export`).
   - Жодного TypeScript.
   - Бекенд: Node.js v24 з нативним модулем `node:sqlite` (робота без сторонніх npm-залежностей).
   - Фронтенд: Чистий Vanilla JavaScript (ESM у браузері через `<script type="module">`), семантичний HTML5, модульний чистий CSS, графіки на нативному HTML5 Canvas 2D API.
2. **База даних**:
   - SQLite (`data/morpho.db`).
   - Обов'язкове ввімкнення режиму `PRAGMA journal_mode = WAL;` для паралельного читання клієнтами під час фонового запису.
3. **Обмеження оформлення (Суворо)**:
   - Повна заборона використання будь-яких емодзі та смайликів у вихідному коді, текстах інтерфейсу, документації та звітах.

```
│   ├── services/

│   │   ├── riskMetrics.js      # Розрахунок буфера ліквідації, штрафів LLTV > 90%, множників застави

    │   ├── main.css            # Фінтех темна палітра, базові стилі, типографіка, сітка
    │   └── components.css      # Стилі карток, бейджів ризику, часової шкали та Canvas
    └── js/
        ├── app.js              # Контролер інтерфейсу, взаємодія з API сервера, морфінг
        ├── sphere.js           # Автентична 3D-сфера частинок Morpho на WebGL/Three.js
        └── ui.js               # Оновлення компонентів DOM (вердикт, список ринків, таймлайн)
```

## 3. Детальний Покроковий Roadmap

### Фаза 1: Проєктування та Створення Бази Даних (Database Layer)
- [x] **Крок 1.1**: Створити директорію `data/` та налаштувати модуль `server/db/database.js` із використанням вбудованого `node:sqlite`. Налаштувати прагми `journal_mode = WAL`, `synchronous = NORMAL`, `foreign_keys = ON`.
- [x] **Крок 1.2**: Розробити схему бази даних `server/db/schema.js`:
  - `vaults`: ідентифікатор, адреса, мережа (Chain ID), назва, символ, куратор, базовий актив, decimals, поточний стан.
  - `markets`: унікальний ключ, loan token, collateral token, oracle, irm, lltv, decimals, поточні supply/borrow/fee.
  - `vault_allocations`: поточні та історичні частки капіталу волту у підпорядкованих ринках.
  - `reallocations`: журнал подій `vaultReallocates` (хеш, блок, мітка часу, тип операції, суми assets/shares).
  - `daily_apys`: щоденні історичні ставки прибутковості для калібрування Монте-Карло.
  - `vault_snapshots`: періодичні зрізи метрик (TWR-30d, TWR-90d, Safety Score, Liquidity Coverage).
  - `sync_state`: журнал останніх синхронізованих блоків і міток часу для уникнення повторних завантажень.

### Фаза 2: Клієнт Джерела Даних та Синхронізатор (Ingestion Engine)
- [x] **Крок 2.1**: Реалізувати модуль запитів `server/services/morphoApi.js`:
  - Базовий нативний клієнт `fetch` до `https://api.morpho.org/graphql`.
  - Запити: список усіх активних MetaMorpho Vaults (Ethereum та Base), повна інформація по ринках, вибірка `vaultReallocates` з пагінацією.
  - Механізм тротлінгу (250 мс затримки між запитами) та повторних спроб (Backoff).
- [x] **Крок 2.2**: Реалізувати нормалізатор `server/services/normalizers.js`:
  - Конвертація сирих значень `BigInt` з урахуванням decimals активів у стандартні числові значення.
  - Розрахунок чистих відсотків та ліквідності ринків.
- [x] **Крок 2.3**: Реалізувати воркер синхронізації `server/services/syncEngine.js`:
  - Первинне наповнення бази історичними даними по топ-сховищах.
  - Періодичний цикл (раз на 60 секунд) для довантаження нових блоків і транзакцій.

### Фаза 3: Математичне та Аналітичне Ядро (Analytical Core)
- [x] **Крок 3.1**: Реалізувати `server/engine/riskMetrics.js`:
  - Обчислення ризику за формулою буфера ліквідації: $\text{Buffer} = 1 - \text{LLTV}$.
  - Застосування множників активів застави (WETH: 1.0, LST: 1.2, LRT/Синтетики: 1.5, Екзотика: 2.0).
  - Застосування штрафу за стиснений буфер при LLTV > 90% (Leverage Squeeze).
- [x] **Крок 3.2**: Реалізувати `server/engine/twrCalculator.js`:
  - Розрахунок Time-Weighted Risk за дискретними часовими вікнами (останні 30 днів, 90 днів, All-Time).
  - Врахування як активних транзакцій куратора, так і пасивного дрейфу балансів.
  - Детекція Peak Risk Spikes: виявлення епізодів, коли миттєвий ризик перевищував критичні пороги.
- [x] **Крок 3.3**: Реалізувати `server/engine/liquidityEngine.js`:
  - Розрахунок вільної ліквідності маркетів: $\text{FreeLiquidity} = \text{TotalSupply} - \text{TotalBorrow}$.
  - Розрахунок показника Liquidity Coverage Ratio ($\text{FreeLiquidity} / \text{VaultDeposit}$).
  - Розрахунок Vault Dominance (% від загальної пропозиції ринку, який контролюється цим сховищем).
- [x] **Крок 3.4**: Реалізувати `server/engine/verdictEngine.js`:
  - Нормалізація TWR у шкалу Safety Score від 0 до 100 балів.
  - Генерація інвесторських попереджень (Red Flags): висока концентрація, небезпечні сплески ризику, низька ліквідність виходу.

### Фаза 4: Серверний API (HTTP REST Layer)
- [x] **Крок 4.1**: Реалізувати маршрутизатор `server/api/routes.js` на базі нативного `node:http`:
  - `GET /api/vaults`: список усіх сховищ із базовими рейтингами, APY та статусом ліквідності (дефолтний ліміт 300, сортування за ліквідністю).
  - `GET /api/vaults/:address`: детальний аудит конкретного сховища (розбивка за ринками, показники TWR-30/90, історія релокацій, спайки ризику, параметри для Монте-Карло).
  - `GET /api/status`: стан синхронізації та актуальність даних.
  - `POST /api/sync`: запуск оновлення актуальних даних за запитом (у фоновому або очікуваному режимі).
- [x] **Крок 4.2**: Налаштувати роздачу статичних файлів клієнта (`client/`) та підтримку CORS для прямого відкриття фронтенду.

### Фаза 5: Клієнтський Інтерфейс та Canvas Монте-Карло (Frontend UI)
- [x] **Крок 5.1**: Створити розмітку `client/index.html` та стилі `client/css/main.css`, `client/css/components.css`:
  - Шапка з індикатором свіжості даних (Live 413 Vaults).
  - Рядок пошуку над сферою з автокомплітом та підсвічуванням кульок на 3D-сфері.
  - Розмітка 3-панельного модального дашборду морфінгу (photo_2, photo_4).
  - Секція графіка вартості депозиту Монте-Карло з інтерактивними перемикачами сум ($1,000 - $100,000) та терміну (30 - 365 днів).
  - Секція аудиту куратора: таймлайн релокацій та журнал Peak Risk Spikes.
  - Таблиця підпорядкованих ринків зі статусом покриття ліквідності.
- [x] **Крок 5.2**: Архітектурний модуль специфікацій волту та видалення Монте-Карло:
  - Повне вилучення модуля симуляцій Монте-Карло (chart.js, canvas, пресети сум та горизонтів) з UI та API.
  - Впровадження блоку Vault Architecture & Specifications (базовий позиковий актив, адреса контракту токена, кількість активних ринків, комісія куратора, мережа).

- [x] **Крок 5.3**: Реалізувати 3D-сферу частинок `client/js/sphere.js` та головний контролер `client/js/app.js`:
  - 1,200 частинок за алгоритмом спіралі Фібоначчі за зразком morpho.org (photo_3).

  - Зв'язування з бекенд REST API та живими ончейн-даними.

## 5. Інструкції для Наступного Агента

1. **Оновлення статусу**: Після завершення будь-якого кроку позначте відповідний пункт у списку `[x]` і додайте новий запис у таблицю `Журнал Виконання Робіт`.
